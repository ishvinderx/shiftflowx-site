# AI SEO — audit + pass, 2026-08-09

Goal: make shiftflowx.net extractable and citable by AI engines (ChatGPT, Perplexity,
Claude, Copilot) and AI buying agents, without writing anything "for AI" — Google AI
Overviews follows core Search, and separate-content-for-AI risks the scaled-content
spam policy.

## What was already in place (verified, no action)

- **robots.ts** allows every AI crawler that cites (GPTBot, ChatGPT-User, ClaudeBot,
  anthropic-ai, PerplexityBot, Google-Extended, Bingbot, Applebot) — and CCBot too,
  which is a deliberate openness choice (blocking CCBot would stop Common Crawl
  training without affecting citation; revisit if that trade-off changes).
- **llms.txt** existed with CORRECT pricing (the wrong-pricing defect from the
  2026-08-03 backlog was already fixed).
- **JSON-LD** on layout (SoftwareApplication + Organization), home (FAQPage + offers),
  blog posts (Article with datePublished/dateModified), use-case pages.
- **Topical cluster** for query fan-out: 5 use-case pages + 8 blog guides covering the
  fan-out neighbours of "shift tracking / payroll errors / gig taxes / payday".
- **SSR everywhere** — pricing renders in initial HTML (client component, but constants
  are compiled in; no fetch, no login wall).

## What this pass added

1. **`/pricing.md`** — machine-readable pricing for AI agents, as a **build-time route**
   (`src/app/pricing.md/route.ts`) rendered from the SAME `PRICING` constants the
   pricing page shows. Deliberately not a static file: a third hand-maintained copy of
   the prices is exactly the W-3 coupling hazard the scope doc warns about.
2. **`/pricing` structured data** — SoftwareApplication + Offers and FAQPage JSON-LD,
   server-rendered in `pricing/page.tsx`, built from `PRICING` and the new
   `BILLING_FAQ` constant. The FAQ array moved from `PricingClient` into
   `constants.ts` so the schema can never describe questions the page doesn't show.
3. **llms.txt refresh** — `Last updated` stamp, Key Pages link section, and a pointer
   to `/pricing.md` as the canonical machine-readable pricing.

## Deliberately NOT done (and why)

- **Comparison pages naming competitors (W-1)** — still operator-gated: comparative
  claims about named companies need verified facts; a fast build raises legal risk.
  These are the single highest-citation content type (~33% of AI citations), so they
  are the top item once facts are verified. Note: publish them as neutral,
  criteria-led comparisons — self-promotional "best X" listicles mostly earn citations
  in answers that recommend competitors.
- **Social proof (W-2)** — never fabricate ratings/counts; needs real ASC numbers.
- **Review-site / Reddit / Wikipedia presence** — AI engines cite third-party sources
  6.5x more than brand domains; this is real-participation work, not a site change.

## Monitoring (monthly, manual — no AI-specific Search Console exists)

Run these through ChatGPT (search on), Perplexity, and Google; log cited-or-not + who:
1. "best shift tracking app for gig workers"
2. "app that catches payroll errors / underpayment"
3. "ShiftFlow pricing" (should draw from /pricing or /pricing.md)
4. "how to track work hours for taxes canada"
5. "payday prediction app"
6. "invoice app for self-employed hourly workers"
Watch: citation vs. RECOMMENDATION framing (cited-but-competitor-recommended means the
consensus layer — reviews/forums — needs work, not the site).

## Update rule

When ASC prices change (A-4 territory pricing!): change `constants.ts` ONLY —
/pricing, /pricing.md and the schema all follow. `llms.txt` still carries a prose copy
of the USD prices + its `Last updated` line: update both by hand (grep for `9.99` in
`public/llms.txt`).
